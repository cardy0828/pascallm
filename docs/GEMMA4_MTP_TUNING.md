# Gemma 4 12B の学習不要な MTP 高速化

[English](GEMMA4_MTP_TUNING.en.md)

転記や差分編集では、プロンプトの中に正しい続きがすでにあることが多い。API の `-mtp-lookup 3` は、同じ要求の確定済みトークンから続きを提案し、本体で検証する。一致する履歴がなければ通常の assistant が3候補を生成する。7を指定すると、8トークン以上一致したときだけ最大7候補に伸ばす。探索は直近4,096トークン、最短一致は4トークン。別の要求やキャンセル後に履歴を持ち越さず、prefix cache を復元した場合も今回の入力から履歴を作る。

固定3候補の通常の貪欲生成では、`-mtp-integrated` で候補生成・本体4行の検証・連続受理数の判定を1本の CUDA Graph にまとめられる。API と gemma4-gpu の両方で使える。FP16 KV が必要。両方の設定を有効にすると、履歴で提案できないバッチで一体 Graph を使う。残り文脈が短い場合は従来経路に戻る。

以下は転記向けの設定例。金額や時刻だけが変わる行では誤った続きを提案しやすく、今回の測定では履歴3候補で約25〜27%遅くなった。

起動時に、対応する assistant と固定3候補を指定する。両機能とも既定は無効。サンプリングや文法で実際の選択トークンを照合する経路は従来どおり。API の generation_metrics ログに、実行した方式の integrated_batches と lookup_batches を記録する。個別の draft_gpu_ms・verify_gpu_ms はこれらのバッチを含まず、batch_wall_ms は含む。

```bash
./bin/pascallm-server -architecture gemma4 -pq4 data/gemma4-12b-qat.pq4m \
  -tokenizer-dir data/m7-api/tokenizer -mtp /path/to/assistant.gguf \
  -kv-cache fp16 -mtp-draft 3 -mtp-integrated -mtp-lookup 3
```

## 開発時の実測

GTX 1080 Ti、Gemma 4 12B IT QAT の PQ4 本体と4層 assistant、FP16 KV、貪欲生成。単位は生成 tok/s。入力処理と起動を除く。履歴比較は各方式で準備運転し、最大128生成で順序を変えて測った中央値。上の2条件は各3回、下の2条件は各4回。全試行で生成 ID と長さが本体単独に一致した。

| 用途 | 既存 MTP | 履歴最大3 | 履歴最大7 |
|---|---:|---:|---:|
| 案内文の転記 | 134.36 | 155.45 | 164.37 |
| 用紙の色だけ変更 | 138.78 | 152.47 | 145.90 |
| 毎行時刻が変わる CSV | 142.95 | 107.45 | 未測定 |
| 金額・日数が変わる請求明細 | 139.04 | 102.06 | 未測定 |

一体 Graph は別試験。KLD 入力24 / 1,024 / 4,092トークンの順に、既存 MTP の124.67 / 99.01 / 110.26 tok/s に対し124.97 / 99.32 / 110.60 tok/s だった（各4組、128生成）。丸めた中央値での差は約0.2〜0.3%。GPU 受理判定・読み戻しの集約・区間計時の省略を含む。両方式を併用した速度向上率はこの試験から求められない。

固定4行の分岐候補は試作で、直列の合計時間を分岐方式の合計時間で割ると、6入力で1.015倍、別の4入力では1.007倍、常時分岐は最初の6入力で0.888倍。候補生成器の語彙削減も CSV の1条件で速くなった一方、日本語説明と Go では遅くなった。これらは公開ランタイムの設定には採用していない。
