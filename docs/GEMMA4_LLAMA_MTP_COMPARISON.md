# Gemma 4 12B: llama.cppとのMTP比較

2026-11-17にGTX 1080 Tiで測定しました。この条件では、MTPありのPascaLLMは比較対象のllama.cppに対して1.21〜1.51倍の生成速度でした。特定のビルドと少数の入力による測定であり、他のGPU・モデル・バージョンでの性能を保証するものではありません。

## 比較対象と条件

- PascaLLM: 公開初版 `8c0178b292d18ba5df915ced2929b47730141bc7` 相当の検証済みソースからビルド。
- llama.cpp: [tvall43/llama.cpp](https://github.com/tvall43/llama.cpp) の `e98d01d92d789147d33ac1caf89b08c4416bf504`。既存のCUDAビルドを使用。upstream最新版との比較ではありません。
- GPU: GTX 1080 Ti 1枚、Linux。両者とも全層GPU、K/VはFP16、context上限8192、同時要求1件。
- モデル: Gemma 4 12B IT QAT。GGUFは `gemma-4-12B-it-qat-UD-Q4_K_XL.gguf`。ファイル名にQ4_K_XLを含みますが、対象行列はQ4_0です。PascaLLMは同じGGUFから値を変えずPQ4に詰め替えた重みを使用しました。
- MTP: 両者とも `mtp-gemma-4-12B-it.gguf`、最大3候補。PascaLLMの候補数自動調整は無効。
- llama.cpp: Flash Attention有効、batch/ubatch 512、CPU threads 6、`--spec-type draft-mtp`。CUDA Graphの再利用をログで確認。
- thinking無効、seed 42、top_k 40、top_p 0.95、min_p 0.05、繰り返しペナルティ1、presence/frequency penalty 0。
- 各モードでwarmup後、5入力を順に3周。計60要求。KV再利用なし（全要求cached_tokens=0）、入力トークン数は両者で一致。
- 実行順はllama.cpp通常→llama.cpp MTP→PascaLLM通常→PascaLLM MTPで固定。クロック固定・順序の無作為化は行っていません。

## 使用した入力

- 日本語説明: 「光合成の仕組みを日本語で詳しく説明してください。」
- Goコード: 「Goで文字列のスライスから重複を除去する関数を書き、動作も説明してください。」
- 計算説明: 「120円のりんごを3個、200円の梨を2個買い、1000円払いました。計算の手順とお釣りを説明してください。」
- 物語: 「雨の日に古い図書館を訪れた学生の短い物語を書いてください。」
- 識別番号抽出: 冒頭を「資料を読み、最後の質問に答えてください。\n案件の識別番号は6274です。\n」とし、「記録000: 図書館の資料は毎週整理され、利用者は受付で貸出の手続きを行います。」から記録063までの64行を改行で連結。末尾に「\n案件の識別番号だけを答えてください。」を追加。

## 出力と解釈上の制約

- PascaLLMでは今回の5入力すべて、MTP有無の本文が一致しました（各3回）。
- llama.cppでは計算説明・識別番号抽出はMTP有無で一致し、日本語説明・Goコード・物語は異なりました。temperature 0の日本語説明・Goコードでも差があり、原因は未切り分けです。
- 各モード内の同一入力3回は本文が一致しました。ただし、同じseedでも異なる実装間で同じサンプリング結果になるとは限りません。
- 識別番号抽出以外は128トークン上限による途中終了です。コード全体の実行正当性、計算の最終回答、文章全体の品質は評価していません。
- 生成文が異なる条件も含むため、同一の出力トークン列を固定したカーネル単体の性能比較ではありません。MTP受理率は出力内容にも依存します。
- ツール呼び出し、複数セッション、8192トークンを満たす長文脈、多数の課題による品質評価は対象外です。
