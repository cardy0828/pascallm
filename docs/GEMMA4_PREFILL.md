# Gemma 4 12B のプレフィル

[English](GEMMA4_PREFILL.en.md)

GTX 1080 Ti 1枚で、入力65,536トークンのプレフィルに307.39秒かかった。以下は2026-11-19の開発版での測定。公開版には同じカーネルを収録している。重みは Gemma 4 12B IT QAT の対応 Q4_0 GGUF を PQ4 に詰め替えたもの。KV は FP16、全層 GPU、モデル常駐、MTP 無効、入力ごとに KV をリセットした。

## 採用した変更と測定条件

1. **行列積と最終層**。対応形状の行列積を出力128行×入力64トークンに分割し、最終層では後の生成で必要な K/V だけを計算する。4,096入力ではプレフィルが8.416秒から7.989秒になった（交互に各4回、中央値）。
2. **全文脈・局所 attention**。全文脈層では8個の query ヘッドで K/V を共有し、局所層ではリング容量が2の累乗の場合にビットマスクで参照する。直前の版と比べ、8,191入力で最初の生成 ID まで18.254秒から17.043秒になった（各2回の中央値）。この時間はトークナイズと HTTP を含まない。
3. **長文の全文脈 attention**。共有メモリへの K の書き込みを整列させ、V の集計を履歴8位置ずつ展開した。下表の「直前」は1と2を適用済み。各段階の測定は別々に行った。

| 入力トークン | 直前 秒 | 採用後 秒 | 直前 tok/s | 採用後 tok/s | llama.cpp tok/s |
|---:|---:|---:|---:|---:|---:|
| 4,096 | 7.566 | 7.526 | 541.23 | 544.15 | 564.52 |
| 16,384 | 40.458 | 40.097 | 404.94 | 408.58 | 408.49 |
| 65,536 | 312.461 | 307.389 | 209.74 | 213.20 | 200.55 |

PascaLLM はチャンク幅512。最後の入力は別途 Feed するため、速度は（入力長 − 1）÷ プレフィル秒。16K は実行順を入れ替えて各2回の中央値、4K・64K は各1回で、実行間のばらつきは評価していない。各長さで変更前後の末尾全語彙 logits のハッシュと次の greedy ID が一致した。

llama.cpp は同じ GPU と元 GGUF、Flash Attention 有効。[比較対象のビルド](https://github.com/tvall43/llama.cpp/commit/e98d01d92d789147d33ac1caf89b08c4416bf504) の llama-bench に `-ngl 99 -fa 1 -b 512 -ub 512 -p 4096,16384,65536 -n 0 -r 1 -t 6` を指定した。各長さ1回。入力内容と末尾トークンの計時範囲が異なる。

## チャンク幅と最大長

API サーバーと gemma4-gpu は `-prefill-chunk` で1〜1,024を指定できる。既定は512。4,096入力で幅512から1,024にすると、最初の ID まで7.580秒から7.502秒に短縮し、GPU全体の観測ピークは134 MiB増えた（各3回の中央値を用いた時間比較）。

11 GiB の実機では `-compact-vram -prefill-chunk 256 -max-context 262144` で重み・KV・作業領域を一括確保した。局所 KV を保存位置に巻き戻せる幅はチャンク幅（最小8）になる。ホスト側の prefix snapshot は独立している。

長文用の最終調整前に、262,128入力と生成用16位置で上限262,144への到達を確認した。プレフィル3,831.07秒、観測ピーク11,105 MiB。同条件で MTP assistant を載せる余裕はなかった。最終調整後はモデル全体を65,536入力まで測定し、最大長の末尾128位置は合成入力の attention 単体で確認した（各2回の中央値463.34 → 447.72 ms、出力一致）。
